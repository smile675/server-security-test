# Contribution Guide

Thank you for your interest in contributing to this project!
This project aims to provide a simple, ethical, and educational tool for testing server flood-resistance and protection mechanisms. Your contributions — whether code, bug reports, documentation improvements, or suggestions — are highly appreciated.

---

## 1. How to Contribute

### Fork & Clone
1. Fork this repository to your own GitHub account.  
2. Clone your fork locally:  
   ```bash
   git clone https://github.com/your-username/server-security-test.git
   cd server-security-test
   ```
### Create a Branch
1. Always create a new branch for your changes:
    ```bash
    git checkout -b feature/your-feature-name
    ```
2. Use descriptive names, e.g., fix/latency-calculation, feature/json-output, etc.

### Make Changes
- Add new features, fix bugs, or improve documentation.
- Ensure code style is consistent (PEP8 for Python).
- Add comments where necessary.
- Test Your Changes
- Run the scripts locally in a Python virtual environment.
- Make sure your changes do not break existing functionality.
- Optional: Add new tests if adding functionality.

### Commit & Push
    ```bash
    git add .
    git commit -m "Brief description of your changes"
    git push origin feature/your-feature-name
    ```
### Open a Pull Request (PR)
- Go to your fork on GitHub and click New Pull Request.
- Provide a clear description of what your PR does.
- Reference any issues your PR closes (e.g., Closes #3).

## 2. Guidelines
- Be respectful and professional in all discussions.
- Focus on safety: this project deals with flood-resistance testing. Do not include scripts that can harm servers you do not own.
- Keep changes modular and well-documented.
- Ensure your code works on Windows, macOS, and Linux if possible.

3. Ways to Contribute
- Code: Add new features or fix bugs.
- Documentation: Improve README, usage instructions, and examples.
- Testing: Suggest test cases, verify compatibility, and share results.
- Ideas & Suggestions: Open issues for feature requests or improvements.
